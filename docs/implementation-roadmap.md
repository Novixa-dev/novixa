## ١. مبادئ خارطة الطريق (Execution Principles)

1. **العمل التراكمي دون هدم (In-Place Engineering):** تطوير وتحسين المنظومة البرمجية الحالية القائمة في المستودع دون إنشاء مشروع موازٍ أو استبدال التقنيات المتفق عليها.
2. **الإنجاز المكتمل لكل مرحلة (Definition of Done):** لا تُعتبر أي ميزة أو شاشة مكتملة بمجرد رسم واجهتها البصرية؛ بل يجب أن تتصل بمخزن بيانات حقيقي (`Store`) وتعمل خوادم الإدخال والمعالجة (`Server Actions`) وتنجح الاختبارات الآلية بنسبة 100%.
3. **الأولوية للأثر والتحويل التشغيلي:** اكتمال لوحة الإدارة وإتاحة إدارة الكتالوج والمحتوى والطلبات يدوياً يمثل أولوية قصوى لتمكين صاحب العمل من تشغيل أعماله فوراً.

- [x] إنشاء متتبع المهام والتقدم `docs/TASK_PROGRESS_TRACKER.md`.

### المرحلة ب (Phase B): تحديث دقة المنتجات والتحويل في الواجهة العامة · **IN PROGRESS**
- [x] تدقيق مسميات وحالات المنتجات: Aqar (يبدأ من $500 كترخيص مخصص)، Muhajim (مجاني)، Pulse (قيد التطوير والتخطيط).
- [ ] ضمان دقة رسائل الـ CTA ونماذج الاتصال لتوجيه العميل نحو المنتج المناسب.
- [ ] ربط مسارات التنقل العامة بالكتالوج المحدث.

### المرحلة ج (Phase C): إكمال لوحة الإدارة وعمليات الـ CRUD الشاملة (Dashboard Complete Management) · **CURRENT FOCUS**
1. **إدارة الطلبات المتكاملة (`Leads Full Management`):**
   - إضافة إمكانية إنشاء طلب عميل جديد يدوياً من داخل لوحة الإدارة (`Manual Lead Intake`) عبر زر مخصص ونموذج شامل.
   - إضافة إمكانية تعديل كافة تفاصيل العميل (الاسم، البريد، الهاتف، الشركة، الميزانية، التفاصيل).
   - توثيق النشاط التلقائي لكل عملية إنشاء أو تعديل في الـ Timeline.
2. **إدارة الكتالوج والخدمات والحلول (`Catalog & Services Management`):**
   - تحويل `/admin/services` من مجرد شاشة قراءة ثابتة إلى لوحة تحكم تفاعلية متكاملة.
   - دعم إنشاء وتعديل وحذف وتغيير حالة الخدمات الهندسية والحلول الجاهزة والمنتجات السحابية والقطاعات.
   - اشتراط توافر النصين العربي والإنجليزي لكل مدخل حفاظاً على مبدأ (Arabic-First).
3. **إدارة الأسئلة الشائعة (`FAQ Management`):**
   - إنشاء صفحة `/admin/faq` لإضافة وتعديل وحذف الأسئلة الشائعة بلغتيها وتصنيفاتها.
4. **إدارة المقالات والرؤى التقنية (`Insights & Articles Management`):**
   - إنشاء صفحة `/admin/insights` للتحكم في مقالات المدونة الهندسية والتحديثات التقنية.
5. **إدارة سابقة الأعمال والمشاريع (`Case Studies & Work Management`):**
   - إنشاء صفحة `/admin/work` لإدارة نماذج المشاريع وحالات الدراسة ومستويات إنجازها.
6. **طبقة التخزين الموحدة (`Content & Catalog Store`):**
   - بناء `src/lib/content-store/` لدعم العمل في الذاكرة (مع بذر البيانات التلقائي من الكود القائم) ودعم قاعدة بيانات PostgreSQL.

### المرحلة د (Phase D): برنامج الشركاء والمسوقين (Affiliate & Partner Program)
- [ ] بناء شاشة إدارة الشركاء `/admin/affiliates` لتسجيل المسوقين، تحديد نسب العمولات (30% افتراضياً)، تسجيل المبيعات المحققة، وسجل تدقيق العمولات والمستحقات.
- [ ] توفير صفحة تعريفية عامة لبرنامج الشركاء توضح الشروط وآلية الانضمام والأرباح بنزاهة تامة.

### المرحلة هـ (Phase E): المبادرات المجتمعية وحملات هدايا المطورين (Community Campaigns)
- [ ] بناء شاشة إدارة الحملات والمبادرات `/admin/campaigns` لإنشاء الحملات (مواقع الفعاليات المجتمعية، هدايا مواقع المطورين الشخصية).
- [ ] إدارة ومراجعة طلبات المتقدمين (جديد، قيد المراجعة، مقبول، مرفوض) وتوثيق القرارات.

### المرحلة و (Phase F): الاختبارات الشاملة والاعتماد والتسليم (Verification & Handover)
- [ ] تشغيل اختبارات الأنواع `npm run typecheck` والتأكد من خلوها من أي خطأ.
- [ ] تشغيل فحص التنسيق والجودة `npm run lint`.
- [ ] تشغيل اختبارات الوحدات والتكامل `npm test`.
- [ ] تشغيل بناء الإنتاج `npm run build` للتأكد من سلامة الحزم والتوليد الثابت.
- [ ] حفظ التغييرات وعمل Git Commits نظيفة ورفعها إلى GitHub.
- [ ] تسليم التقرير النهائي المفصل باللغة العربية.
