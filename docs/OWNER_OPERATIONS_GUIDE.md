# دليل تشغيل نوڤيكسا — للمالك

كيف تفتح موقعك وتختبره، وكيف تدخل لوحة الإدارة، وكيف تستقبل بريد `@novixa.dev`
وتقرؤه وتربطه بهاتفك وحاسوبك، وكيف تشغّل كل ذلك يوماً بيوم.

**آخر تحديث:** ٢٠٢٦-١٠-٠٩ · **حالة الموقع:** يعمل على `https://novixa.dev`

> **المستودع عام.** لذلك لا يحوي هذا الدليل أي كلمة مرور أو مفتاح، ولن يحويها أبداً.
> يذكر أين كل سرّ محفوظ وكيف تستعيده أو تغيّره، لا قيمته. لا تكتب كلمة مرور في
> أي ملف داخل المشروع، ولا في رسالة commit، ولا في طلب دمج.

## 2. كيف تختبر موقعك

### أ) الفحص الآلي السريع (دقيقة واحدة)

من مجلد المشروع على جهازك، في Git Bash:

```bash
bash scripts/verify-live.sh
```

يفحص 29 نقطة دون أن يغيّر شيئاً أو يرسل نموذجاً: صحة الموقع والإصدار المنشور، التوجيه
(`/` ← `/ar`، و`www` ← النطاق الأساسي، و`http` ← `https`)، ترويسات الأمان، canonical
وhreflang وصورة المشاركة، خريطة الموقع وrobots، وأن لوحة الإدارة خاصة وغير مفهرسة.
النتيجة السليمة: `RESULT: 29 passed, 0 failed`.

وللتحقق السريع من الصحة وحدها افتح https://novixa.dev/api/health. السليم:

```json
{"status":"ok","version":"<رقم الإصدار>","database":"ok","store":"postgres","mail":"smtp"}
```

`version` هو أول 12 رمزاً من آخر commit نُشر، فتتحقق أن ما يعمل هو آخر ما دمجتَه.

### ج) الاختبار الكامل لطلب حقيقي (الأهم)

هذا يثبت أن الموقع يجمع الطلبات فعلاً ويصلك بريدها:

1. افتح `https://novixa.dev/ar/contact` (أو `/ar/start-project`).
2. أرسل طلباً ببريدك الشخصي (مثلاً Gmail) واكتب في التفاصيل «اختبار».
3. يجب أن تظهر رسالة نجاح.
4. افتح **صندوق `hello@novixa.dev`** (القسم 4): تصلك رسالة بعنوان
   `New project inquiry — <اسمك>` وفيها زر **Open in the admin**. الرد عليها يذهب إلى
   بريد الزائر مباشرة لأن `Reply-To` مضبوط عليه.
5. افتح **بريدك الشخصي**: تصلك رسالة عربية «استلمنا طلبك — نوڤيكسا (Novixa NVX-…)».

6. افتح **لوحة الإدارة** (القسم 3): الطلب ظاهر في أعلى القائمة.
7. احذف طلب الاختبار من لوحة الإدارة.

> **طلب اختبار واحد موجود الآن في قاعدة البيانات**: أنشأته أنا أثناء الفحص (الاسم
> «اختبار تقني - نشر الموقع»، الرقم `NVX-MV00L6JL`). احذفه من لوحة الإدارة.

### د) اختبار سمعة بريدك (mail-tester)

1. افتح https://www.mail-tester.com وانسخ العنوان الذي يعرضه (`test-xxxx@srv1.mail-tester.com`).
2. أرسل طلباً من نموذج الموقع واكتب هذا العنوان كبريد للزائر (هكذا يرسل الموقع رسالة
   التأكيد إليه من `no-reply@novixa.dev`).
3. اضغط «Then check your score».

القياس الأول (قبل تعديل قالب الرسالة) كان **8.3 من 10**، والمصادقة (SPF وDKIM وDMARC)
كلها سليمة. خُصم 1.29 بسبب قاعدتين تُخطئان في النص العربي (الموضوع «كله كبير»)، وقد عُدّل
القالب لإصلاحهما، ويُتوقع نحو 9.6. وخُصم 0.56 لأن النطاق جديد (أقل من 7 أيام)، وهذا

## 3. لوحة الإدارة `/admin`

### أ) كيف تفتحها

1. افتح https://novixa.dev/admin (تنتقل تلقائياً إلى صفحة الدخول إن لم تكن مسجَّلاً).
2. **البريد:** `admin@novixa.dev`
3. **كلمة المرور:** التي كتبتَها عند ضبط `ADMIN_PASSWORD`.
4. تبقى مسجَّلاً **12 ساعة**، ثم تدخل من جديد. زر الخروج في الشريط العلوي.

حماية الدخول: 10 محاولات خاطئة كل 15 دقيقة لكل عنوان IP، ورسالة خطأ واحدة لا تكشف أي
الحقلين خاطئ، وكعكة الجلسة `Secure` و`HttpOnly` و`SameSite=Strict`. اللوحة **غير
مفهرسة** ومحظورة في `robots.txt`. وفيها زر لتبديل اللغة بين العربية والإنجليزية.

### ب) ماذا فيها

| الصفحة | الرابط | ماذا تفعل |
|---|---|---|
| **نظرة عامة** | `/admin` | إجمالي الطلبات، آخر 7 و30 يوماً، الطلبات التي لم يُرد عليها، المتعاقَد معهم، رسم يومي لآخر 30 يوماً، توزيع حسب المرحلة والمصدر، وحالة النظام (القاعدة والبريد والإصدار) |
| **الطلبات** | `/admin/leads` | قائمة 25 في الصفحة، بحث، تصفية حسب المرحلة والمصدر، **تصدير CSV** (يُفتح بالعربية سليمة في Excel) |
| **تفاصيل الطلب** | `/admin/leads/<رقم>` | كل ما كتبه الزائر، أزرار مراسلة مباشرة، تغيير المرحلة، ملاحظات داخلية، حذف بتأكيد |

**مراحل الطلب:** جديد — لم يُرد عليه ← تم التواصل ← مؤهَّل ← عرض مُرسَل ← تم التعاقد
(أو: لم يكتمل / غير جاد-مزعج). **مصدر الطلب:** نموذج التواصل، أو «ابدأ مشروعك». أوقات
العرض بتوقيت عدن.

### ج) اختبرها خطوة بخطوة (5 دقائق)

1. ادخل بالبريد وكلمة المرور ← تظهر **نظرة عامة**.
2. جرّب كلمة خاطئة عمداً ← رسالة خطأ، ولا تدخل.
3. أرسل طلب اختبار من الموقع (القسم 2-ج) ← يظهر في **الطلبات** وفي «لم يُرد عليه».
4. افتحه ← غيّر المرحلة إلى «تم التواصل»، واكتب ملاحظة، ثم **حدّث الصفحة**: يجب أن
   يبقى التغيير والملاحظة.
5. من **الطلبات** اضغط تصدير CSV وافتح الملف في Excel ← العربية سليمة.
6. جرّب البحث باسم الطلب أو رقم الإيصال `NVX-...`، وجرّب تصفية المرحلة.
7. احذف طلب الاختبار ← يختفي ويعود العدّاد.
8. اخرج، ثم افتح `/admin/leads` مباشرة ← تُحوَّل إلى صفحة الدخول (اللوحة لا تُعرض بلا دخول).

### د) نسيتَ كلمة المرور، أو تريد تغييرها

كلمة المرور لا تُخزَّن نصاً في أي مكان: يحوّلها خط النشر إلى بصمة مشفّرة (scrypt) قبل أن
تصل إلى الخادم. فالتغيير هو **ضبط سرّ جديد ثم إعادة النشر**:

```bash
read -rs -p "ADMIN_PASSWORD (12+): " P; echo; echo "length: ${#P}"; printf '%s' "$P" | gh secret set ADMIN_PASSWORD --env production --repo Novixa-dev/novixa; unset P
```

```bash
gh workflow run deploy.yml --repo Novixa-dev/novixa --ref main
```

بعد انتهاء النشر (≈ 5 دقائق) ادخل بالكلمة الجديدة. تأكد أن `length:` **12 أو أكثر** وإلا
يرفض خط النشر الكلمة. لتغيير **بريد** الدخول: `gh secret set ADMIN_EMAIL ...` ثم النشر.

### هـ) حدود اللوحة الحالية

- هي لوحة **إدارة الطلبات** (CRM بسيط)، وليست نظام إدارة محتوى: **لا تعدّل بها نصوص
  الصفحات ولا المقالات ولا الصور**. المحتوى كله في ملفات الكود (`src/content/`) ويتغيّر
  عبر طلب دمج. الخطة المقترحة لبناء إدارة المحتوى في `docs/IMPLEMENTATION_PLAN.md` (المرحلة 9).
- حساب مدير واحد فقط، بلا مستخدمين ثانويين ولا صلاحيات ولا مصادقة ثنائية.
- لا تنبيه فوري على الهاتف عند وصول طلب (يصل بريد فقط). الخيار المقترح: بوت Telegram
  (`docs/NEXT_STEPS.md` الخطوة 10).

## 4. بريد `@novixa.dev`

### أ) العناوين الموجودة الآن

| العنوان | نوعه | يعمل كـ |
|---|---|---|
| `hello@novixa.dev` | **صندوق** | الصندوق الرئيسي: تصله كل طلبات الموقع، وهو مقرؤك اليومي |
| `no-reply@novixa.dev` | **صندوق** | يرسل منه الموقع رسائل التأكيد للزوار فقط. لا تستعمله للقراءة |
| `postmaster@novixa.dev` | بديل (alias) ← `hello@` | عنوان قياسي تُرسل إليه تقارير DMARC وتنبيهات الخادم |
| `admin@novixa.dev` | بديل (alias) ← `hello@` | اسم الدخول إلى لوحة الموقع، ويستقبل البريد أيضاً |

**الفرق بين الصندوق والبديل:** الصندوق له كلمة مرور ومساحة وتدخل إليه. البديل مجرد
**اسم آخر يوجّه إلى صندوق**، فلا تدخل إليه، بل تقرأ رسائله في الصندوق الذي يوجّه إليه.

الحدود الحالية في النطاق (قابلة للتعديل من mailcow ← Domains ← Edit): 10 صناديق، و400
بديلاً، و10 جيجابايت إجمالاً. حجم `hello@` بلا حد، و`no-reply@` 1 جيجابايت.

### ب) اقرأ بريدك على الويب

1. افتح https://mail.novixa.dev/SOGo/
2. **اسم المستخدم:** العنوان كاملاً (`hello@novixa.dev`). **كلمة المرور:** كلمة الصندوق.
3. تجد البريد والتقويم وجهات الاتصال. للرد: افتح الرسالة واضغط «رد».

### ج) اربطه بتطبيق البريد في هاتفك أو حاسوبك

أدخل هذه القيم **يدوياً** في أي تطبيق (Outlook وThunderbird وApple Mail وGmail وتطبيقات
الأندرويد وiPhone):

| | القيمة |
|---|---|
| الخادم (للاستقبال والإرسال) | `mail.novixa.dev` |
| **استقبال IMAP** (الأفضل) | المنفذ **993**، التشفير **SSL/TLS** |
| استقبال POP3 (بديل) | المنفذ **995**، التشفير SSL/TLS |
| **إرسال SMTP** | المنفذ **465** (SSL/TLS) أو **587** (STARTTLS) |
| اسم المستخدم | **العنوان كاملاً**، مثلاً `hello@novixa.dev` |
| كلمة المرور | كلمة ذلك الصندوق |
| المصادقة | كلمة مرور عادية (Normal password) |

> استعمل **IMAP** لا POP3 إن أردت قراءة البريد من أكثر من جهاز (هاتف وحاسوب) فيبقى
> متزامناً. POP3 ينزّل الرسائل إلى جهاز واحد.

**الإعداد التلقائي (اختياري):** يعمل ربط الحسابات بكتابة البريد وكلمة المرور فقط إن وُجدت
سجلات `autodiscover` و`autoconfig` في DNS، وهي **غير موجودة الآن**. أضفها في Cloudflare
← DNS ← Add record (نوع **CNAME**، **DNS only** (سحابة رمادية))، فتعمل بدون إدخال القيم يدوياً:

| Name | Target |
|---|---|
| `autodiscover` | `mail.novixa.dev` |
| `autoconfig` | `mail.novixa.dev` |

(إعداد nginx في mailcow يقبل هذين الاسمين أصلاً، وشهادتهما يطلبها mailcow تلقائياً.
الإعداد اليدوي أعلاه يعمل دائماً بدونهما.)

### د) كيف تستقبل **كل** البريد المرسَل إلى أي عنوان `@novixa.dev`

لديك ثلاث طرق، من الأفضل إلى الأقل نصحاً:

**1) عناوين محددة تقرؤها كلها في صندوق واحد (الموصى بها).**
أنشئ بديلاً لكل عنوان تريده يوجّه إلى `hello@novixa.dev`، فيصلك كل شيء في مكان واحد:

mailcow ← **E-Mail** ← **Configuration** ← تبويب **Aliases** ← **Add alias**:
- **Alias address/es:** `info@novixa.dev` (يمكن كتابة عدة عناوين معاً)
- **Goto addresses:** `hello@novixa.dev`

عناوين شائعة يُنصح بها: `info` و`sales` و`support` و`contact` و`security` و`abuse`.

**2) صندوق مستقل لكل شخص.**
Mailboxes ← **Add mailbox**: اسم المستخدم والنطاق وكلمة مرور. لكل موظف صندوقه وكلمته.

**3) التقاط الكل (Catch-all).**
أي بريد لأي عنوان غير موجود (`xyz@novixa.dev`) يصل إلى صندوق واحد:

Aliases ← **Add alias** ← **Alias address/es:** `@novixa.dev` (بلا شيء قبل `@`) ←
**Goto:** `hello@novixa.dev`.

> **تحذير:** هذا يجعل صندوقك يستقبل **كل** الرسائل العشوائية والمزعجة الموجَّهة لعناوين
> مخمَّنة، فيمتلئ بالسبام. الأفضل الطريقة (1). فعّله فقط إن احتجتَه فعلاً.

### هـ) اقرأ كل شيء في Gmail (اختياري)

**الاستقبال:** عدّل البديل ليصل أيضاً إلى Gmail، فتستلم نسخة في Gmail وفي `hello@`:
Aliases ← عدّل البديل ← **Goto addresses:** `hello@novixa.dev, عنوانك@gmail.com`.

**الإرسال باسم نوڤيكسا من Gmail:** في Gmail ← الإعدادات ← **Accounts and Import** ←
**Send mail as** ← Add another email address ← الاسم والعنوان `hello@novixa.dev` ←
SMTP Server: `mail.novixa.dev`، المنفذ `587`، اسم المستخدم `hello@novixa.dev`، كلمة مرور
الصندوق، **Secured connection using TLS** ← أكّد عبر رمز يصل إلى `hello@`.

### و) إرسال بريد من نوڤيكسا بسمعة جيدة

الحالة الحالية (تحققتُ منها): **SPF** و**DKIM** و**DMARC** منشورة وصحيحة، و**PTR** (العنوان
العكسي) = `mail.novixa.dev`. اختبار mail-tester أكّد أن المصادقة سليمة وأن النطاق غير
مدرج في قوائم الحظر. نصائح:

- ابدأ بكميات صغيرة من النطاق الجديد، ولا ترسل رسائل جماعية من `hello@`.
- DMARC الآن `p=none` (مراقبة فقط). بعد **أسبوعين** من تقارير نظيفة غيّره في Cloudflare
  إلى `p=quarantine` (السجل `_dmarc`).
- صندوق `no-reply@` محدود بـ **60 رسالة في الساعة** لحماية سمعتك إن تسرّبت كلمته.

### ز) استعادة كلمات المرور وإدارة mailcow

| المطلوب | كيف |
|---|---|
| نسيتَ كلمة **صندوق** | mailcow ← Mailboxes ← **Edit** على الصندوق ← كلمة جديدة (زر generate) ← Save |
| نسيتَ كلمة **مدير mailcow** | على الخادم: `cd /opt/mailcow-dockerized && ./helper-scripts/mailcow-reset-admin.sh` |
| غيّرتَ كلمة `no-reply@` | حدّث السرّ `SMTP_PASSWORD` في GitHub ثم أعد النشر (القسم 3-د: نفس الخطوتين) |
| سجلات البريد (لماذا لم تصل رسالة؟) | mailcow ← **System** ← **Logs** (Postfix وDovecot) |

### ح) النسخ الاحتياطي للبريد — **غير مضبوط بعد**

نسخ **قاعدة بيانات الموقع** ليلي ومفعَّل (القسم 5). أما **رسائل البريد نفسها** (محتوى
الصناديق) فهي على خادم mailcow وحده ولا يغطيها هذا النسخ. إن تلف القرص ضاع البريد.
خياران:

- **لقطات Contabo** (Snapshots / Auto Backup): أسهل، **وهي خدمة قد تكلّف مالاً**، فتحقق
  من السعر في لوحتك قبل التفعيل.
- **نسخ mailcow الرسمي** إلى مجلد ثم نسخه خارج الخادم:

```bash
cd /opt/mailcow-dockerized
MAILCOW_BACKUP_LOCATION=/opt/mailcow-backup ./helper-scripts/backup_and_restore.sh backup all
```

أياً كان الاختيار، **انسخ الناتج خارج الخادم** (جهازك أو تخزين سحابي تملكه).

### ط) إن لم تصل رسالة

1. افحص مجلد **Spam/Junk** في الصندوق.
2. mailcow ← System ← Logs ← Postfix: ابحث عن العنوان.
3. من الموقع: إن كانت الاستجابة `"delivered": false` فالطلب **محفوظ** في لوحة الإدارة لكن
   البريد لم يُرسَل (راجع `SMTP_PASSWORD` وصندوق `no-reply@`).
4. اختبر السمعة عبر mail-tester (القسم 2-د).

## 5. التشغيل اليومي

### النشر

كل دمج في `main` يشغّل: اختبارات كاملة (CI) ← بناء الصورة ← نسخة احتياطية للقاعدة ←
تشغيل الإصدار الجديد مع فحص صحة ← **رجوع تلقائي إن فشل** ← فحص الموقع عبر Cloudflare. لا
تدخل لك. للنشر اليدوي دون دمج جديد: Actions ← **Deploy** ← Run workflow، أو:

```bash
gh workflow run deploy.yml --repo Novixa-dev/novixa --ref main
```

### الرجوع إلى إصدار سابق

على الخادم، بمستخدم `novixa`: `/opt/novixa/scripts/deploy.sh ghcr.io/novixa-dev/novixa sha-<commit قديم>`.
أو اعمل revert على `main` ودع النشر التلقائي ينشره.

### السجلات

```bash
ssh root@161.97.75.64
cd /opt/novixa && docker compose logs -f app
```

سطر `Error: Internal: NoFallbackError` في السجل **عادي**: يظهر عند زيارة روبوتات لمسارات
غير موجودة، والرد 404 صحيح.

### النسخ الاحتياطي للقاعدة

- **تلقائي** كل ليلة 02:17 (UTC) وقبل كل نشر، في `/opt/novixa/backups`، ويُحتفظ بآخر 14 يوماً.
- **يدوي الآن:** `runuser -u novixa -- /opt/novixa/scripts/backup.sh manual`
- **استعادة:** `/opt/novixa/scripts/restore.sh backups/<الملف>.dump` (يطلب تأكيداً ويأخذ نسخة
  من الحالة الحالية أولاً).
- **تنبيه:** هذه النسخ على **نفس قرص الخادم**، فهي تحميك من خطأ حذف أو ترحيل سيئ، **لا من
  ضياع الخادم**. انسخ المجلد خارج الخادم دورياً (انظر 4-ح).

### الأسرار (GitHub ← Settings ← Environments ← production)

`ADMIN_EMAIL` · `ADMIN_PASSWORD` · `SMTP_PASSWORD` · `CF_ORIGIN_CERT` · `CF_ORIGIN_KEY` ·
`VPS_HOST` · `VPS_PORT` · `VPS_USER` · `VPS_KNOWN_HOSTS` · `VPS_SSH_KEY`. المتغيرات (غير سرّية):
